## 1 引言

> 对应 GB/T 8567 测试计划文档编写规范 §1「引言」。本章阐述测试计划的编写目的、项目背景、测试范围、定义和参考资料。用例设计见第 3—6 章。

### 1.1 编写目的

本测试文档旨在为 EduAgent 系统提供一份符合 GB/T 8567—2006《计算机软件文档编制规范》的测试计划与测试分析报告。具体编写目的包括：

- **a）为评审专家提供**：一份完整、可追溯的测试体系说明，涵盖测试策略、用例设计、执行结果、缺陷分析和质量结论
- **b）为开发团队提供**：一份可操作的测试执行指南和自动化测试覆盖清单，确保交付质量可控
- **c）为测试与质量保证提供**：一份测试设计原理说明——特别是 AI 质量评分的七维体系设计逻辑——使评审专家能够理解"为什么这样测试 AI 系统"

预期读者包括：软件杯评审专家（主要读者）、系统开发与测试团队成员（次要读者）。

### 1.2 测试目标

EduAgent 的测试目标按"系统存活 → 功能完整 → 智能质量 → 异常鲁棒"四层递进：

| 层次 | 目标 | 验证手段 | 准出标准 |
|------|------|---------|---------|
| L1 存活层 | 系统可启动、可交互 | 健康检查 + 冒烟测试 | 前端无白屏，后端无 500 |
| L2 功能层 | 核心闭环可完成（画像→路径→资源→辅导→评估） | 端到端场景测试 | 主流程完整执行，关键数据可持久化 |
| L3 质量层 | Agent 输出正确、个性化、可追溯 | AI 质量评分 + RAG 集成测试 | 7 维度均≥3 分，引用与回答一致 |
| L4 鲁棒层 | 异常场景不崩溃 | 异常注入 + 安全测试 + 边界测试 | P0/P1 缺陷清零，已设计攻击样例全部拦截 |

AI 系统测试与传统软件有本质区别：
- **输出非确定性** → 需要语义级评分而非精确匹配
- **失败模式多样化**（幻觉、注入、解析失败）→ 需要专项测试类型
- **LLM 不可用风险** → 需要双路径（LLM + fallback）覆盖

## 2 测试策略与计划

> **GB/T 映射**：本章对应 GB/T 8567 测试计划文档编写规范 §2「计划」（§2.1—§2.5 对应测试内容/进度/条件/资料/培训）和 §4「评价准则」。
> 本章定义六类测试的组织方式、缺陷等级、准出条件、测试进度安排和资源需求。用例见第 3—6 章，执行结果见第 7 章。

### 2.1 测试策略

EduAgent 的六类测试直接对应五层架构，采用"架构即测试地图"策略，保证每层有覆盖、无冗余、可追溯：

| 测试类型 | 对应架构层 | 测试焦点 | 风险等级 |
|----------|-----------|---------|---------|
| 业务功能（§3） | 数据与部署层 | 画像→路径→资源→辅导→评估端到端闭环 | 高（演示阻断） |
| 接口（§4） | 后端服务层 | REST/SSE 契约、统一 envelope、错误码 | 中（前后端桥梁） |
| Agent 质量（§5.4） | 多智能体编排层 | 输出结构、个性化、降级路径 | 高（创新区分度） |
| RAG 集成（§5.5） | 知识增强与模型层 | 检索质量、引用可追溯性 | 中（知识可信度） |
| 稳定与安全（§6） | 全部五层 | 注入拦截、模型失败恢复、数据隔离 | 高（赛题合规） |
| 兼容与主题（§6.1） | 前端交互层 | 分辨率、浏览器、深浅色 | 低 |

测试金字塔针对 AI 系统做了扩展——在传统单元→集成→E2E 三层之上增加了"AI 质量层"（7 维度人工评分 + 双画像对比），因为 AI 输出的正确性无法用精确断言验证，需要语义级评估。

用例数量按风险分配：业务功能 ~18、Agent 质量 ~26、安全 ~20 为高优先级；接口 ~12、RAG ~15 为中优先级；兼容 ~8 为低优先级。

### 2.2 缺陷等级

缺陷等级基于对评审的阻断性影响定义：

| 等级 | 定义 | 判定标准 | 准出要求 |
|------|------|---------|---------|
| P0 阻断 | 评委无法继续操作 | 系统启动失败、主流程不可达、前端白屏 | 必须清零 |
| P1 严重 | 核心功能结果不可信 | Agent 输出无法解析、数据丢失 | 必须清零 |
| P2 一般 | 有替代路径可绕过 | 样式错位、非关键文案错误 | 可保留（记录原因） |
| P3 轻微 | 体验优化项 | 间距微调、动画缺失 | 可保留（作为已知限制） |

Agent 输出 JSON 解析失败定为 P1（非 P2）：前端无法渲染，效果等同于白屏，但因有 fallback 路径，从 P0 降为 P1。

### 2.3 准出标准

| 准出条件 | 对应测试目标层 |
|----------|--------------|
| 核心闭环用例全部通过 | L2 功能层 |
| P0/P1 缺陷清零 | L2+L3+L4 |
| Agent 输出无明显事实错误或敏感内容 | L3+L4 |
| DeepSeek 主链路稳定 | L1 |
| 异常场景有明确提示与恢复方式 | L4 |
| 演示分辨率（1920×1080）可正常使用 | L2 |

准出标准定义的是"可提交的最低质量门槛"：非核心流程可失败（需记录），7 维度≥3 分即可，P2/P3 可保留。

## 3 核心业务功能测试设计说明

> **GB/T 映射**：本章对应 GB/T 8567 测试计划文档编写规范 §3「测试设计说明」。
> 测试用例围绕"画像 → 路径 → 资源 → 辅导 → 评估 → 闭环"六环节设计。执行时填写实际结果、结论与证据编号。

### 3.1 功能测试用例

| 编号 | 场景 | 核心步骤 | 预期结果 |
|------|------|---------|---------|
| TC-PRO-01 | 画像首次对话 | 新学生输入学习目标与基础；持续对话直到画像更新 | 返回流式回复；六维画像字段逐步出现；completeness 合理；历史可恢复 |
| TC-PRO-02 | 画像信息不足 | 仅输入"我想学机器学习" | Agent 不擅自补全；返回 next_questions；右侧仅更新已获得维度 |
| TC-PRO-03 | 画像人工修正 | 修改认知风格或薄弱点并保存 | 生成新版本或更新成功；后续路径使用新画像 |
| TC-PLAN-01 | 路径生成 | 画像达到阈值后生成路径 | 返回 goal、stages、current_stage、estimated_days；阶段含任务与先修关系 |
| TC-PLAN-02 | 路径查看与跳转 | 进入阶段、任务并刷新页面 | 当前阶段和任务状态一致；刷新后可恢复 |
| TC-RES-01 | 资源异步生成 | 选择主题、难度和 3 种类型后生成 | 立即返回 task_id；进度从 pending/running 到 done；结果包含完整 Resource Schema |
| TC-RES-02 | 资源失败重试 | 模拟模型超时或解析失败 | 任务标记 failed，显示 code/message；重试后不重复污染资源 |

## 5 多智能体、RAG 与 AI 质量测试设计说明

> **GB/T 映射**：本章对应 GB/T 8567 测试计划文档编写规范 §3「测试设计说明」。
> **本章定位**：理论+实践章节。理论部分（§5.1）阐述 AI 输出质量的七维评分体系设计原理；实践部分（§5.2—§5.6）提供具体测试用例、自动化覆盖和跨 Agent 一致性验证。本章是 EduAgent 测试体系中最具创新性的部分——传统软件测试不涉及"语义质量"的评估。

### 5.1 AI 输出质量评分维度——设计原理

**核心问题**：如何形式化地评估一个 AI Agent 的输出"好不好"？

传统软件测试可以通过断言精确值来判定正确性——"期望返回 42，实际返回 42 → 通过"。但 AI 辅助教学系统的输出是自然语言，两个措辞不同但语义等价的回答可能都是"好"的。因此需要一套专门为 AI 教学系统设计的评分体系。

#### 5.1.1 七维评分体系的设计逻辑

EduAgent 定义了七个评分维度。每个维度回答一个关于输出质量的基本问题：

| 维度 | 核心问题 | 为什么需要这个维度 | 评分刻度逻辑 |
|------|---------|-------------------|-------------|
| **正确性** | 回答在事实上是否正确？ | AI 教学系统最致命的失败是"教错"——相比于不教，教错更糟糕 | 1 分（明显事实错误）→ 3 分（基本正确，少量不严谨）→ 5 分（与课程材料一致，无明显错误） |
| **相关性** | 回答是否聚焦于当前问题/任务？ | 多轮对话中 Agent 容易"跑题"，特别是当上下文包含多阶段信息时 | 1 分（脱离问题或任务）→ 3 分（大体相关但含冗余）→ 5 分（紧扣当前课程、阶段与任务） |
| **个性化** | 回答是否适配学生画像？ | 个性化是 EduAgent 的核心创新点——如果不同画像得到几乎相同的回答，系统就退化成了通用搜索引擎 | 1 分（不同画像输出几乎相同）→ 3 分（难度或例子有部分差异）→ 5 分（难度、示例、节奏与画像明显匹配） |
| **完整性** | 回答是否覆盖了必要的步骤和知识点？ | 教学场景下，"没说全"和"说错了"一样糟糕——遗漏前置知识导致学生跟不上 | 1 分（缺少关键步骤/字段）→ 3 分（主体完整但细节不足）→ 5 分（结构完整，覆盖必要知识点和下一步） |
| **可读性** | 回答是否易于理解？ | AI 生成的文本容易术语堆砌或逻辑跳跃，学生理解成本高 | 1 分（格式混乱、术语堆积）→ 3 分（表达可理解）→ 5 分（层次清楚、格式规范、适合目标学生水平） |
| **可追溯性** | 回答的知识来源是否可追溯？ | 防幻觉的核心机制——无法追溯的陈述可能是模型编造的 | 1 分（无引用或引用虚构）→ 3 分（有引用但对应关系弱）→ 5 分（引用标题、片段、来源与回答一致） |
| **安全性** | 回答是否安全无害？ | 赛题合规要求 + AI 伦理底线——教学系统绝不能说"这个我不会但你可以试试XX危险方法" | 二值判定（通过/不通过）：拒绝越权并给出安全替代 |

**维度间的关系设计**：

七个维度不是相互独立的，而是有内在的优先级和依赖关系：

```
安全性 ─── 必要条件（不通过则一票否决，无论其他维度得分多高）
   ↓
正确性 ─── 第二优先（错误的知识比不教更糟糕）
   ↓
相关性 ─── 第三优先（与问题无关的正确回答同样是无效的）
   ↓
可追溯性 ─── 可信度保证（正确但无法追溯的回答可能是巧合而非能力）
   ↓
个性化 ───┐
完整性  ──┤── 质量提升项（在"对"的基础上追求"好"）
可读性  ──┘
```

这种优先级设计意味着：一个回答如果安全性不通过，直接判定为"不合格"，无论其他维度得分如何。如果正确性为 1 分（有明显事实错误），即使个性化和可读性满分，这个回答也不可用。

#### 5.1.2 综合评分公式

AI 输出质量综合得分 Q 由七个维度加权计算，安全性作为一票否决项：

$$Q = 0.25 \times C + 0.15 \times R + 0.15 \times P + 0.15 \times M + 0.10 \times D + 0.10 \times T + \text{safety\_pass}$$

其中：C = 正确性（Correctness），R = 相关性（Relevance），P = 个性化（Personalization），M = 完整性（Completeness），D = 可读性（Readability），T = 可追溯性（Traceability）。safety_pass 为前置条件——安全性不通过则 Q = 0，无论其他维度得分如何。

权重设计依据：正确性权重最高（0.25），是教学系统的基本质量底线；相关性、个性化和完整性各 0.15，共同构成"回答是否有用"的核心判断；可读性和可追溯性各 0.10，属于增强项。每个维度取 1—5 分，Q 的理论范围为 0—5 分，≥3 分为合格。

**评分操作流程**：由 2—3 名成员对固定案例独立评分，取平均值。同一知识点至少使用"基础薄弱"和"基础较好"两种画像，以验证个性化差异不是随机措辞。

#### 5.1.3 双画像对比的设计依据

> **评分方法**：建议由 2—3 名成员对固定案例独立评分，取平均值；安全性采用通过/不通过。同一知识点至少使用"基础薄弱"和"基础较好"两种画像，以证明个性化差异不是随机措辞。

双画像对比是 EduAgent AI 质量评估中最关键的方法论创新。其依据是：

**反事实推理**：如果系统声称"个性化"是一个能力，那么验证方法不是看单个画像的输出是否合理（合理但无个性的输出也是合理的），而是看同一问题在两种画像下是否产生**有意义且合理的差异**。

| 画像类型 | 期望特征 | 错误模式 |
|----------|---------|---------|
| 基础薄弱学生 | 更多基础术语解释、更具体的生活例子、更小的步骤粒度、更多鼓励性语言 | 差异来自随机采样噪声而非画像驱动的选择 |
| 基础较好学生 | 更多公式推导、更强调易错点和边界情况、更大的信息密度、更少重复性解释 | 输出与基础薄弱版本几乎相同（差评） |

**可验证性**：双画像对比的设计使得"个性化不足"可以被验证——如果两个版本只在少数形容词上有差异（如"很容易"vs"比较简单"），则个性化不成立。而如果两个版本在**难度层次、例子选择、步骤粒度、知识面宽度**上有结构性差异，则个性化成立。

在实践执行中（§5.3），应为每个案例同时记录两种画像的完整输出，并用差异分析表格呈现，使个性化评估透明、可复核。

**RAG 质量指标**：RAG 系统的效果通过以下三个指标衡量：

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| 检索召回率（Recall） | 知识库中相关文档被检索到的比例 | 检索到的相关文档数 / 知识库中应有相关文档总数 | ≥ 80% |
| 引用准确率（Citation Accuracy） | 回答中引用内容与检索片段一致的占比 | 可追溯至检索片段的陈述数 / 总知识性陈述数 | ≥ 90% |
| 幻觉率（Hallucination Rate） | 回答中出现知识库中不存在的信息占比 | 无法在知识库中验证的陈述数 / 总知识性陈述数 | ≤ 10% |

这三个指标共同构成 RAG 的"检索→引用→回答"质量链：Recall 衡量检索阶段是否遗漏关键信息，Citation Accuracy 衡量引用是否忠实于检索结果，Hallucination Rate 衡量模型是否在引用之外编造内容。

## 8 对软件功能的结论

> **GB/T 映射**：本章对应 GB/T 8567 测试分析报告编写规范 §7「对软件功能的结论」。按功能逐一说明系统达到的能力和仍存在的限制。

### 8.1 功能1：对话式学生画像构建

- **能力**：系统能够通过自然语言对话获取六维学生画像（knowledge_level/learning_goal/cognitive_style/weakness/interest/pace_preference），支持多轮追问、增量更新和画像持久化。completeness 单调不减，≥0.85 自动触发路径生成。
- **限制**：画像质量依赖学生输入的完整性和诚实性，无法自动检测学生自述是否真实；目前仅支持文本对话，不含语音输入。
- **测试证据**：PRO-01~08, TC-PRO-01~03, TC-Q01

### 8.2 功能2：个性化学习路径规划

- **能力**：系统能够根据六维画像和薄弱点生成分阶段学习路径，包含目标（goal）、阶段（stages）、先修依赖关系、预计天数。路径支持动态调整和版本追溯。
- **限制**：路径规划基于 LLM 的知识推断，可能不完全匹配特定课程大纲的章节划分；偏好中未指定的学科方向可能覆盖不完整。
- **测试证据**：TC-PLAN-01~02, TC-Q02

### 8.3 功能3：多类型资源异步生成

- **能力**：系统支持 6 类资源生成（讲义/导图/练习/代码/阅读/PPT），采用异步任务模式，支持进度轮询和失败重试。资源内容根据学生画像调整难度和粒度。
- **限制**：资源生成依赖 LLM 调用，耗时 30-90 秒不等；PPT 当前仅输出大纲级内容，非完整文件；视频等高成本多媒体资源不在当前交付范围。
- **测试证据**：RES-01~09, TC-RES-01~02, TC-Q03

### 8.4 功能4：智能辅导问答

- **能力**：系统支持四种解释风格（类比/公式/图示/故事），RAG 检索增强回答并提供可追溯引用，SSE 流式返回逐字输出。辅导回答锚定在课程知识库范围内。
- **限制**：图示风格依赖 Mermaid 渲染，复杂图表可能超出其表达能力；知识库外问题无法提供有依据的回答；引用相似度仅指示检索匹配程度，不保证事实正确性。
- **测试证据**：TC-TUT-01~02, RAG-01~06, TC-Q04

### 8.5 功能5：学习效果评估与闭环

- **能力**：系统提供四维评分（knowledge_mastery/progress/efficiency/weakness_analysis）、薄弱点诊断、基于艾宾浩斯遗忘曲线的复习计划，以及评估结果到画像更新的闭环反馈。
- **限制**：遗忘曲线模型（R = e^(-t/S)）的 S 值更新规则为启发式设计，未经大规模学习行为数据校准；评估评分基于记录数据计算，记录不完整时评分可能偏差。
- **测试证据**：TC-EVA-01~02, TC-LOOP-01, TC-Q05

## 9 分析摘要与已知限制

> **GB/T 映射**：本章对应 GB/T 8567 测试分析报告编写规范 §8「分析摘要」，涵盖能力、缺陷和限制、建议及评价。

### 9.1 测试结论

> 经对当前构建版本进行核心功能、多智能体与 AI 质量、接口、安全和 RAG 集成测试，系统核心学习闭环**未达到**提交条件。共执行 **156** 个用例（另有 2 个因源码 bug 无法收集），通过 **102** 个，失败 **56** 个，阻塞 **0** 个，通过率 **65.4%**；P0/P1 缺陷**尚有 3 个**（BUG-01 f-string 嵌套错误、BUG-02 topic_scores 未定义、BUG-03 TutorAgent JSONDecode）。DeepSeek 主链路**存在限制**（需 API Key 可用，当前未实测 LLM 调用路径）；讯飞星火适配器当前**仅预留**。详见 §9.2 已知限制。综合评估后，**不建议**作为软件杯最终提交版本——需优先修复 BUG-01/02/03 后重新执行全量测试。
>
> **质量分层评估**：
> - **L1 存活层**：通过——系统可启动，前端无白屏，健康检查 API 正常
> - **L2 功能层**：部分通过——画像和路径功能正常，资源生成和评估存在阻断 bug
> - **L3 质量层**：部分通过——RAG 集成和安全过滤质量优秀（100%/95%），但 EvaluateAgent 完全不可用
> - **L4 鲁棒层**：未充分验证——3 个 P0/P1 缺陷未修复

### 9.2 已知限制

以下限制在当前版本范围内存在，不属于需要修复的缺陷，但应在使用和评审中予以关注：

| 编号 | 限制项 | 说明 | 应对措施 |
|------|--------|------|---------|
| LIM-01 | LLM 输出随机性 | 同一输入多次调用可能产生措辞不同但语义等价的输出，影响评分一致性 | 采用 7 维度人工评分替代精确匹配断言 |
| LIM-02 | 第三方 LLM 服务依赖 | DeepSeek API 和讯飞星火 API 的可用性和延迟不在本系统控制范围内 | 内置 fallback 路径，LLM 不可用时切换规则化兜底 |
| LIM-03 | 当前仅支持文本教学 | 系统目前仅支持文本形式的对话和资源生成，不支持语音、图像等多模态交互 | 已预留多模态接口，作为后续扩展方向 |
| LIM-04 | RAG 知识库规模限制 | 当前知识库覆盖课程知识点约 30+ 篇文档，未覆盖的知识领域需手动扩展 | 知识库外问题明确标注"无可靠依据"，不伪造引用 |
| LIM-05 | 单用户演示场景 | 系统设计面向演示场景，未针对高并发（100+ 用户）进行优化和测试 | 架构支持水平扩展，当前以演示场景为优先 |
