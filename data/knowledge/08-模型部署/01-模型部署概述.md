# 模型部署概述

## 1. 概念定义

模型部署是将训练好的机器学习模型集成到生产环境中，使其能够对外提供推理服务的完整流程。部署涉及模型格式转换、推理优化、服务封装和运维监控等多个环节。

---

## 2. 模型导出

### 2.1 ONNX（Open Neural Network Exchange）
ONNX 是一种开放的模型交换格式，允许在不同框架之间互操作。

- **PyTorch 导出**：torch.onnx.export(model, dummy_input, "model.onnx")
- **Sklearn 导出**：通过 sklearn-onnx 库将传统 ML 模型转为 ONNX
- **优势**：跨框架互操作、硬件加速支持（TensorRT/OpenVINO）

### 2.2 模型序列化
- **PyTorch**：torch.save(model.state_dict()) 保存权重
- **TensorFlow**：model.save() 导出 SavedModel 格式
- **通用方案**：ONNX 或 TorchScript 作为中间格式

---

## 3. 模型优化

### 3.1 模型量化（Quantization）
将模型参数从 FP32 降到 INT8/FP16，减小模型体积和推理延迟。

- **训练后量化（PTQ）**：在已训练模型上直接校准量化参数
- **量化感知训练（QAT）**：训练时模拟量化误差，保持精度
- **效果**：模型体积减少约 75%，推理速度提升 2-4 倍

### 3.2 模型剪枝（Pruning）
移除模型中不重要的权重或神经元，减少计算量。

- **非结构化剪枝**：将接近零的权重置零，生成稀疏矩阵
- **结构化剪枝**：移除整个通道或层，可直接加速推理
- **迭代剪枝**：多次剪枝+微调，逐步压缩模型

---

## 4. 推理服务部署

### 4.1 Flask / FastAPI 推理服务
将模型封装为 HTTP API，客户端通过 REST 请求获取推理结果。

基本流程：
1. 服务启动时加载模型（全局单例）
2. 定义 POST 端点，接收输入数据
3. 预处理输入 → 模型推理 → 后处理输出
4. 返回 JSON 格式的推理结果

### 4.2 OpenCV 推理
使用 OpenCV 的 dnn 模块加载 ONNX 模型进行推理：

- cv2.dnn.readNetFromONNX("model.onnx") 加载模型
- blob = cv2.dnn.blobFromImage(img) 预处理
- net.setInput(blob); output = net.forward() 推理

### 4.3 后处理
- **分类任务**：Softmax → argmax 获取类别；Top-K 获取多个候选
- **检测任务**：NMS（非极大值抑制）去除重叠框；置信度过滤

---

## 5. 部署最佳实践

- **批处理（Batching）**：合并多个请求同时推理，提高 GPU 利用率
- **模型预热（Warmup）**：启动时运行几次空推理，避免首次请求延迟
- **健康检查**：提供 /health 端点，监控服务状态
- **版本管理**：使用模型注册中心（MLflow/Weights & Biases）管理模型版本

---

## 6. 常见误区

- 误区：量化后的模型精度一定会大幅下降 → 事实：8-bit 量化通常精度损失 < 1%，尤其是在大模型上
- 误区：部署就是写一个 Flask API → 事实：生产级部署还需考虑负载均衡、模型版本管理、A/B 测试、监控告警等
- 误区：ONNX 模型总是比原框架快 → 事实：ONNX 主要价值在于跨框架互操作，推理速度取决于运行时引擎

---

## 7. 关键要点

- 模型导出（ONNX/TorchScript）是部署的第一步，确保跨框架兼容
- 量化与剪枝可在保证精度的前提下显著降低推理成本
- Flask/FastAPI 适合轻量级推理服务，生产环境建议搭配 Docker + Nginx
- 后处理逻辑与模型推理同等重要，直接影响最终业务效果
